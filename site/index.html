    How it works

    CelesTrak publishes only the present, so OrbitWatch builds its own history. The whole pipeline runs on GitHub Actions; this page is rebuilt after every run.

    Read the code
    Collect

    Every 6 hours, Dagster downloads the orbit of every object and the satellite catalogue, politely, and retries if CelesTrak is down.

    Land

    Raw bytes are kept exactly as received; typed Parquet files are partitioned by snapshot date.

    Model

    dbt on DuckDB builds the warehouse: type 2 history, orbit changes, re-entries, population and launches.

    Screen

    SGP4 propagates about 20,000 orbits through the next day; a KD-tree screens 200 million pairs for close approaches.

    Publish

    Each day's snapshot and warehouse become a GitHub release, and this page is exported from the warehouse.

    Close approaches are screening candidates from public orbit data (accurate to about a kilometre, degrading over days), not collision probabilities. Satellite operators use covariance-based conjunction data for that.
